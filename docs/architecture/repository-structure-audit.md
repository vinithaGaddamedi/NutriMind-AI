## 3. Mapping from Old → New

| Old Path | New Path |
|---|---|
| `automation/tests/ai/chatbot/` | `ai_testing/deepeval/` |
| `automation/test_data/ai/goldens/` | `ai_testing/golden_datasets/` |

| `backend/` | `application/backend/` |
| `web-app/` | `application/web-app/` |
| `prompts/` | `ai_testing/prompts/` |

## 4. Files That May Have Broken Imports
Moving `backend/` into `application/backend/` will break:
- `automation/tests/ai/chatbot/test_chatbot_e2e.py` (if it imports local python classes directly instead of HTTP requests).
- `automation/unit_tests/test_nutrition.py` or similar backend mocks.

Moving `automation/utils/deterministic_validator.py` to `ai_testing/validators/` will break:
- `automation/tests/ai/chatbot/test_chatbot_e2e.py`
- `automation/unit_tests/test_deterministic_validator.py`

## 5. Files That Should Remain at Root
- `README.md`
- `requirements.txt`
- `.gitignore`
- `.env` and `.env.example`
- `LICENSE`

## 6. Duplicate Functionality
- `.ai/` and `.agents/` overlap. Only `.agents/` should be used.
- `SKILL.md` in the root is orphaned.
- `agents/infrastructure/mcp_playwright_agent.py` and `agents/infrastructure/mcp_server.py` overlap with standard MCP structure. They should be moved to a dedicated root `mcp/` folder as per standard Anthropic/MCP conventions.

## 7. Temporary/Phase Artifacts That Can Safely Be Removed
- `.venv_new/` and `.venv_nutri/` (Duplicate python environments).
- `.ai/` directory.
- Root `SKILL.md`.

## 8. Migration Sequence with Minimal Risk
1. **Clean**: Delete orphaned directories (`.ai/`, `.venv_new/`, `.venv_nutri/`) and `SKILL.md`.
2. **Scaffold**: Create the new empty root directories (`ai_testing/`, `application/`, `mcp/`, `test_data/`).
3. **Migrate Sub-components**: Move `DeepEval`, `golden_datasets`, and `prompts` into `ai_testing/`.
4. **Migrate Infrastructure**: Move `mcp_server` and `mcp_playwright_agent` into `mcp/`.
5. **Migrate SUT**: Move `backend/` and `web-app/` into `application/`.
6. **Import Refactoring**: Run a python search-and-replace script to fix all the newly broken imports.
7. **Validation**: Execute `pytest` locally and trigger a dry run of the E2E lifecycle demo.
